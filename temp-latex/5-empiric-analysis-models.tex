\chapter{Model Architecture, Training and Experimental Protocol}
\label{chap:5-Empiric-analysis-models}
% ============================================================



The preceding chapter characterised the statistical properties of the CIC-IDS2018 dataset and established the analytical foundations required to interpret the noise-injection experiments.  The present chapter describes the full pipeline through which those experiments were designed and executed: from the initial hyperparameter optimisation on a small representative sample of the data, through the derivation of the feature set on which all subsequent experiments operate, to the training of baseline models and the systematic protocol used to evaluate the impact of PuckTrick-injected corruptions.

The chapter is organised as follows.  Section~\ref{sec:model-overview} provides a brief summary of the two model architectures employed and the multi-task prediction formulation shared by both.  Section~\ref{sec:hpo} describes the hyperparameter optimisation procedure, including the search spaces and the Optuna configuration adopted for each model.  Section~\ref{sec:feature-selection} explains the combined feature-importance ranking that was used to derive the final feature set for all experiments.  Section~\ref{sec:baseline-training} describes the temporal split strategy, data scaling, and the sliding-window construction used for the sequence model, together with the baseline performance figures against which every noise-injection result is benchmarked.  Finally, Section~\ref{sec:experiment-protocol} provides a detailed description of the systematic experiment loop executed on the HPC cluster.

\section{Model Architectures and Multi-Task Formulation}
\label{sec:model-overview}
% ============================================================

In order to develop this work following two models were chose, each for different reasons:
\begin{itemize}
    \item
    \item
\end{itemize}

Both architectures were configured as \emph{multi-task classifiers}, jointly predicting two distinct output targets from a shared representation of the input flow:

\begin{itemize}
    \item \textbf{Binary task} (\texttt{label\_generic}): the model predicts whether a flow is benign ($0$) or malicious ($1$), irrespective of the specific attack category. This task is analogous to anomaly detection: the classifier must identify any deviation from normal traffic behaviour.
    \item \textbf{Multi-class task} (\texttt{Label}): the model simultaneously predicts the specific traffic category (Benign or one of 14 mutually exclusive attack types), requiring the classifier to learn fine-grained discriminative representations that distinguish between attack subtypes with often similar flow-level statistics.
\end{itemize}

The joint training of both tasks on a shared encoder has two advantages.  First, it allows the binary and multi-class signals to act as complementary supervisory gradients, potentially regularising the shared representation and improving generalisation.  Second, it makes it possible to detect \emph{asymmetric} effects of data corruption: noise that does not materially degrade binary detection may nonetheless destroy the classifier's ability to resolve attack subtypes, a phenomenon that would be invisible if only one task were monitored.

\subsection{TabNet}
\label{sec:model-tabnet}

TabNet~\supercite{arik2021tabnet} is instantiated as a \texttt{TabNetMultiTaskClassifier} from the \texttt{pytorch-tabnet} library.  It processes the 2D input matrix $(N \times F)$ of raw flow features through a series of $N_{\text{steps}}$ sequential attention steps, each applying a learnable sparse mask to select a subset of features relevant to the current decision step.  The two output heads (\texttt{head\_bin} and \texttt{head\_mul}) branch off from the final aggregated step output.  Categorical and binary features are handled natively through an embedding layer parametrised by \texttt{cat\_idxs} and \texttt{cat\_dims}, while continuous features pass through the shared feature transformer without embedding.

\subsection{CNN-LSTM}
\label{sec:model-cnnlstm}

The CNN-LSTM model is a custom multi-task architecture built on PyTorch.  It receives a 3D input tensor of shape $(B \times T \times F)$, where $B$ is the batch size, $T = 50$ is the temporal window length, and $F$ is the number of features.  The forward pass proceeds as follows:

\begin{enumerate}
    \item \textbf{CNN block:} the input is permuted to $(B \times F \times T)$ so that each feature is treated as a channel.  A single \texttt{Conv1d} layer with $n_{\text{filters}}$ output channels and kernel size $k$ (with symmetric padding to preserve the time dimension) extracts local temporal patterns, followed by ReLU activation, \texttt{MaxPool1d} with kernel~$2$, and \texttt{BatchNorm1d}.
    \item \textbf{LSTM stack:} the output is permuted back to $(B \times T/2 \times n_{\text{filters}})$ and passed through two stacked LSTM layers with hidden sizes $h_1$ and $h_2$.  Only the final hidden state (last time step) is retained, yielding a fixed-length context vector of dimension $h_2$.
    \item \textbf{Shared fully connected block:} a linear layer followed by ReLU and Dropout(p) is applied to the context vector.
    \item \textbf{Task heads:} two independent linear layers project the shared representation onto $n_{\text{bin}} = 2$ and $n_{\text{mul}}$ logits respectively, where $n_{\text{mul}}$ is the number of active multi-class categories after rare-class filtering.
\end{enumerate}

The training loss is the sum of the two cross-entropy losses, one per head.  Gradient clipping (max norm $= 1.0$) is applied at every training step to prevent exploding gradients in the LSTM cells.  A \texttt{ReduceLROnPlateau} scheduler (factor $= 0.5$, patience $= 3$) reduces the learning rate when the validation loss stagnates, and early stopping (patience $= 10$ epochs) terminates training if no improvement is recorded over ten consecutive epochs.

\section{Hyperparameter Optimisation}
\label{sec:hpo}
% ============================================================

Hyperparameter optimisation (HPO) was conducted independently for TabNet and CNN-LSTM using Optuna~\supercite{akiba2019optuna} with the Tree-structured Parzen Estimator (TPE) sampler and the Median Pruner.  The primary design requirement was to obtain well-calibrated hyperparameters without incurring the computational cost of training on the full dataset: accordingly, HPO was performed on a \textbf{0.1\% stratified random sample} of the unified CIC-IDS2018 dataset (stratified by the binary \texttt{label\_generic} column to preserve class proportions), yielding approximately 16\,000 flow records.  This sample was further divided using the same temporal splitting strategy described in Section~\ref{sec:baseline-training}, so that the relative ordering of flows was preserved even at this reduced scale.

The objective function for TabNet was the \emph{mean MCC} across both tasks:
\[
    \mathcal{O}_{\text{TabNet}} = \frac{\mathrm{MCC}_{\text{bin}} + \mathrm{MCC}_{\text{mul}}}{2},
\]
while for CNN-LSTM, because the validation loss is already monitored internally for early stopping and pruning, the objective function returned to Optuna was the \emph{mean F1-score} across both tasks (macro average for the multi-class task):
\[
    \mathcal{O}_{\text{CNN-LSTM}} = \frac{F1_{\text{bin}} + F1_{\text{mul}}}{2}.
\]

Both objectives were maximised. The Median Pruner was configured to discard unpromising trials after a warm-up period of five trials and five internal report steps, allowing early termination of trials whose intermediate metrics fell below the median of all completed trials at the same step.

% ------------------------------------------------------------
\subsection{Batch Size Scaling}
\label{sec:batch-scaling}
% ------------------------------------------------------------

A practical challenge arising from HPO on a $0.1\%$ sample is that the optimal batch size identified on the small sample may be suboptimal when training on the full $10\%$ dataset.  To address this, the linear scaling rule (He et al.) was applied:
\[
    B_{\text{scaled}} = \min\!\Bigl( B_{\text{HPO}} \cdot \frac{0.10}{0.001},\; 4096 \Bigr),
\]
capping the scaled batch size at 4\,096 to avoid excessive GPU memory consumption and prevent the per-batch gradient estimates from becoming excessively noisy at very large sizes.

For TabNet, the sparsity regularisation coefficient $\lambda_{\text{sparse}}$ was also rescaled according to:
\[
    \lambda_{\text{scaled}} = \lambda_{\text{HPO}} \cdot \sqrt{\frac{0.001}{0.10}},
\]
a conservative correction that accounts for the increase in effective gradient magnitude at larger batch sizes while preventing over-regularisation on the larger dataset.

For CNN-LSTM, the learning rate was halved relative to the HPO value to ensure stable convergence at the higher data volume, following common practice in large-batch training protocols.

\section{Feature Importance and Feature Set Selection}
\label{sec:feature-selection}
% ============================================================

A central design choice of the experimental protocol is the selection of the feature set on which both baseline models and all noise-injection experiments operate.  Rather than using the full reduced feature set described in Chapter~\ref{chap:dataset} (44 features for Experiment~A, 79 for Experiment~B), a compact set of \textbf{9 features} was constructed for the baseline experiments through a principled importance-based selection procedure.  This compact set serves three purposes: (i) it makes the computational cost of training both models across hundreds of noise-injection experiments tractable; (ii) it ensures that the features selected for corruption are directly linked to the models' predictive behaviour; and (iii) it provides a controlled experimental setting in which the contribution of each feature can be assessed in isolation.

% ------------------------------------------------------------
\subsection{Feature Importance Extraction}
\label{sec:fi-extraction}
% ------------------------------------------------------------

After identifying the best trial for each model, feature importance scores were extracted using the two mechanisms natively available in the respective architectures:

\begin{itemize}
    \item \textbf{TabNet:} the library exposes \texttt{feature\_importances\_}, an array of shape $(F,)$ representing the mean attention mask weight assigned to each feature across all decision steps and all validation samples.  Features with a high average attention weight are those most frequently selected by the sparse attention mechanism, and can therefore be interpreted as carrying the most discriminative information for both tasks jointly.
    \item \textbf{CNN-LSTM:} since the architecture does not expose a native feature importance measure, \emph{permutation importance}~\supercite{goodfellow2016deep} was employed.  For each feature $i$, the values along feature dimension 2 of the entire validation tensor were randomly permuted across samples (while leaving all other features intact) and the resulting drop in binary classification accuracy, $\Delta_i = \mathrm{acc}_{\text{base}} - \mathrm{acc}_{\text{permuted},i}$, was recorded.  The raw $\Delta_i$ values were normalised to $[0, 1]$ by dividing by the maximum observed drop, yielding a relative importance score $\hat{\Delta}_i \in [0, 1]$.  Negative drops (i.e.\ permuting the feature actually improved accuracy) were clipped to zero.
\end{itemize}

Both models were thus endowed with a ranked list of features ordered by their respective importance scores.

% ------------------------------------------------------------
\subsection{Combined Ranking and Stratified Feature Selection}
\label{sec:combined-ranking}
% ------------------------------------------------------------

Rather than taking the intersection of two top-$k$ lists (which would discard features ranked highly by only one model), a \emph{combined average rank} was computed.  Denoting the rank of feature $f$ in TabNet's list as $r_{\text{TN}}(f)$ and in CNN-LSTM's list as $r_{\text{CL}}(f)$, the combined score is:
\[
    \bar{r}(f) = \frac{r_{\text{TN}}(f) + r_{\text{CL}}(f)}{2}.
\]
The full ranking (78 features) was then sorted in ascending order of $\bar{r}(f)$ (rank 1 = most important).  The top of this ranking is reproduced in Table~\ref{tab:combined-ranking}.

A purely top-$k$ selection from this combined ranking would, however, produce a feature set dominated by high-importance, high-fragility continuous features.  To guarantee a broader coverage of feature types and fragility levels (as classified in Chapter~\ref{chap:dataset}), and to explicitly include features that constitute experimental controls (low-importance or zero-variance features), a \emph{stratified selection} strategy was applied:

\begin{enumerate}
    \item \textbf{Top tier (ranks 1–3):} the three features with the lowest combined rank: \texttt{Fwd Act Data Pkts}, \texttt{Dst Port}, and \texttt{Init Fwd Win Byts}.  These are the most informative features according to both models and are therefore the most likely candidates for performance degradation under noise injection.
    \item \textbf{Middle tier (forced selection for type coverage):} three features were manually selected from the middle of the ranking to ensure adequate coverage of distinct feature types:
    \begin{itemize}
        \item \texttt{Protocol} (combined rank~29): the only low-cardinality categorical feature, essential for the categorical \texttt{labels} noise experiments.
        \item \texttt{PSH Flag Cnt} (combined rank~38): a binary-valued flag feature, included to assess how noise injection interacts with binary features.
        \item \texttt{Fwd Seg Size Min} (combined rank~54): the \emph{only low-fragility} feature in the dataset (see Section~\ref{sec:fragility}), included as a structural control to compare noise sensitivity across fragility classes.
    \end{itemize}
    \item \textbf{Bottom tier (last 3 in combined ranking):} \texttt{Bwd Byts/b Avg}, \texttt{Fwd Blk Rate Avg}, and \texttt{Idle Mean}.  These features are ranked last by both models and include zero-variance bulk-transfer statistics that carry no discriminative information.  Their inclusion provides a negative control: noise injection on features that are already irrelevant to the classifier should, in principle, produce no measurable performance change.
\end{enumerate}

\section{Baseline Model Training}
\label{sec:baseline-training}
% ============================================================

The baseline models constitute the reference against which every noise-injection experiment is evaluated.  They were trained on a \textbf{10\% stratified sample} of the CIC-IDS2018 dataset (stratified by \texttt{label\_generic}) using the nine features selected in Section~\ref{sec:feature-selection} and the hyperparameters from the best HPO trials described in Section~\ref{sec:hpo}.

The 10\% sample was chosen as the largest data volume computationally tractable for iterative model training on a local machine.  It yields approximately \textbf{1\,614\,745 flow records}, retaining the full 15-class label distribution of the original dataset.

% ------------------------------------------------------------
\subsection{Temporal Dataset Split}
\label{sec:temporal-split}
% ------------------------------------------------------------

A fundamental requirement of the experimental design is that the train/validation/test partition \emph{preserves the chronological ordering} of flows.  Shuffling the data before splitting would allow flows from the same temporal burst (e.g., a concentrated DDoS campaign) to appear in both the training and validation sets, artificially inflating performance estimates by contaminating the evaluation with temporally proximate train examples.  This is a well-documented form of data leakage in time-series settings that is particularly dangerous for the CNN-LSTM model, which explicitly exploits temporal context through its sliding-window input representation.

The adopted split strategy is therefore entirely \emph{shuffle-free} and proceeds as follows:

\begin{enumerate}
    \item Flows are sorted in ascending order of \texttt{Timestamp}.
    \item A group index is assigned to each flow: $g_i = i \bmod 3$, where $i$ is the 0-based position in the sorted sequence.
    \item Flows with $g_i \in \{0, 1\}$ (two thirds of the data) form the \emph{training set}.
    \item Flows with $g_i = 2$ (one third, the \emph{temporary set}) are further divided in an interleaved fashion: even-positioned temporary flows ($\text{pos} \bmod 2 = 0$) go to the \emph{validation set}, and odd-positioned flows go to the \emph{test set}.
\end{enumerate}

This produces three non-overlapping partitions that collectively cover all flows in strict chronological order, with no temporal gap between them.  The resulting sizes on the 10\% sample are summarised in Table~\ref{tab:split-sizes}.

% ------------------------------------------------------------
\subsection{Data Preprocessing and Scaling}
\label{sec:preprocessing}
% ------------------------------------------------------------

Following the split, a \texttt{StandardScaler} was fit \emph{exclusively on the training partition} and subsequently applied to both validation and test sets, preventing any target leakage from the evaluation data into the normalisation statistics.  Scaling was applied only to the six continuous features (\texttt{Fwd Act Data Pkts}, \texttt{Dst Port}, \texttt{Init Fwd Win Byts}, \texttt{Bwd Byts/b Avg}, \texttt{Fwd Blk Rate Avg}, \texttt{Idle Mean}); categorical and binary features were left in their integer-encoded form and consumed directly by the respective model heads (through TabNet's native embedding layer, and as integer inputs to the CNN-LSTM channel dimension).

Values containing \texttt{NaN}, \texttt{+inf}, or \texttt{-inf} (arising from division-by-zero artifacts in CICFlowMeter) were replaced with $0$ prior to scaling.

% ------------------------------------------------------------
\subsection{Sliding Window Construction for CNN-LSTM}
\label{sec:windowing}
% ------------------------------------------------------------

The CNN-LSTM model requires a 3D input tensor of shape $(N_{\text{windows}} \times T \times F)$.  Starting from the sorted 2D array of each partition, a sliding window of length $T = 50$ flows with stride $S = 10$ flows was applied:

\[
    X^{(3D)}[j] = X^{(2D)}[jS : jS + T],  \quad
    y^{(3D)}[j] = y^{(2D)}[jS + T - 1],
\]

where the label of each window is the label of its \emph{last} (most recent) flow.  This labelling convention is consistent with a causal streaming detection scenario, in which a decision is made upon observing the most recent packet in the window, using the preceding $T-1$ packets as temporal context.

The resulting tensor dimensions for the 10\% sample baseline are:
\begin{itemize}
    \item Training: $(107\,645 \times 50 \times 9)$
    \item Validation: $(26\,908 \times 50 \times 9)$
\end{itemize}

\section{Experimental Protocol}
\label{sec:experiment-protocol}
% ============================================================

With the baselines established, the principal experimental campaign was executed following a fully automated pipeline implemented in the \texttt{4-4c-cavas\_model\_Experiment\_localhost.py} script.  The pipeline iterates over all combinations of noise injection method, target feature, corruption percentage, and random seed, and for each combination retrains both TabNet and CNN-LSTM from scratch using the best hyperparameters identified in Section~\ref{sec:hpo}.

% ------------------------------------------------------------
\subsection{Experimental Variables}
\label{sec:exp-variables}
% ------------------------------------------------------------

The experimental grid was defined by four independent variables:

\paragraph{Noise injection methods.}
All five PuckTrick corruption methods were employed:
\begin{itemize}
    \item \texttt{missing}: a fraction of values in the target feature column is replaced with \texttt{null}.
    \item \texttt{noise}: values are replaced with uniform random draws from the column's observed range $[\min, \max]$.
    \item \texttt{outliers}: extreme values beyond $\mu \pm 4\sigma$ are injected into numeric columns; the next integer beyond the observed maximum is used for categorical integer columns.
    \item \texttt{labels}: binary labels ($0 \leftrightarrow 1$) are flipped or categorical labels are replaced with a randomly chosen different category.
    \item \texttt{duplicated}: a fraction of rows is duplicated and appended to the dataset.
\end{itemize}

\paragraph{Target features.}
Experiments for the methods \texttt{missing}, \texttt{noise}, \texttt{outliers}, and \texttt{labels} were applied to every feature in the nine-feature set (plus the \texttt{Timestamp} column, for a total of 10 columns), with the constraint that the \texttt{labels} method was applied exclusively to features with binary or categorical semantics (\texttt{FIN Flag Cnt} and \texttt{Protocol}).  The \texttt{duplicated} method operates at the row level rather than the column level and was therefore applied once globally using the \texttt{Timestamp} column as the reference for row selection.

\paragraph{Corruption percentages.}
Six levels of corruption intensity were evaluated:
\[
    p \in \{5\%,\; 10\%,\; 20\%,\; 35\%,\; 50\%,\; 75\%\},
\]
spanning a range from mild, practically plausible degradation to severe corruption that approaches the limits of identifiable signal in the data.

\paragraph{Random seeds.}
To establish confidence intervals around the observed performance deltas and ensure statistical robustness, the entire grid was repeated across \textbf{10 independent random seeds} on the HPC cluster:
\[
    S = \{303,\; 404,\; 505,\; 606,\; 707,\; 808,\; 909,\; 1010,\; 1111,\; 42\}.
\]
Each seed governs the stratified sampling, the temporal split ordering, the PuckTrick noise realisation, and the PyTorch and Lightning random states (via \texttt{pl.seed\_everything}).

% ------------------------------------------------------------
\subsection{Experiment Naming Convention}
\label{sec:exp-naming}
% ------------------------------------------------------------

Each experiment is uniquely identified by a label of the form:
\begin{center}
    \texttt{Experiment\_\{method\}\_\{feature\}\_\{percentage\}}
\end{center}
for example: \texttt{Experiment\_missing\_Dst Port\_50.0}.  For each label, two artifact files are produced: a \texttt{.pt} checkpoint file containing the CNN-LSTM model weights, and a \texttt{\_artifacts.json} file recording all evaluation metrics (MCC, F1, AUC, confusion matrices), the model hyperparameters, the feature importance scores, and the per-feature correlation matrix of the training set.  The TabNet model is persisted as a \texttt{.zip} archive following the \texttt{pytorch-tabnet} serialisation convention.

% ------------------------------------------------------------
\subsection{Dataset Preparation and Caching}
\label{sec:dataset-caching}
% ------------------------------------------------------------

Calling \texttt{prepare\_whole\_dataset\_from\_scratch()} for each experiment would entail: reading the full Parquet file from disk, performing stratified sampling, applying PuckTrick noise injection, converting the Spark DataFrame to Pandas, remapping labels, scaling features, and constructing the sliding windows.  Multiplied across hundreds of experiments and ten random seeds, this would represent a prohibitive I/O and CPU bottleneck.

To circumvent this, the pipeline was executed in two sequential phases:

\begin{enumerate}
    \item \textbf{Dataset compilation phase} (\texttt{JUST\_COMPILE\_DATASETS = True}): all datasets for all experiment combinations were pre-computed and serialised to disk in NumPy binary format (\texttt{.npy} arrays).  For each experiment label, a directory \texttt{<RS\_DIR>/datasets/<label>/} is created, containing the 12 split arrays (train/val $\times$ 2D/3D $\times$ binary/multiclass labels) plus a \texttt{metadata.json} file recording the \texttt{FEATURE\_COLS}, \texttt{CAT\_IDXS}, \texttt{CAT\_DIMS}, \texttt{label\_classes}, and the training-set correlation matrix.  A checkpointing mechanism skips any dataset for which the corresponding \texttt{metadata.json} already exists, making the compilation phase resumable after interruption.

    \item \textbf{Training phase} (\texttt{JUST\_COMPILE\_DATASETS = False}): the training script loads each pre-computed dataset from disk and immediately passes the arrays to the model training functions.  If a model artifact already exists on disk for a given experiment label, training is skipped and the artifact is reloaded directly, making the training phase equally resumable.
\end{enumerate}

This two-phase design decoupled the Spark-intensive data preparation from the GPU-intensive model training, allowing each phase to be scheduled independently on the HPC cluster and enabling efficient use of both the distributed Spark infrastructure and the GPU nodes.

% ------------------------------------------------------------
\subsection{Noise Injection and Dataset Construction per Experiment}
\label{sec:noise-construction}
% ------------------------------------------------------------

For each experiment, the dataset is constructed as follows:

\begin{enumerate}
    \item The full 10\%-sampled Spark DataFrame is loaded from the Parquet archive and restricted to the nine important features plus the mandatory columns (\texttt{Label}, \texttt{label\_generic}, \texttt{Timestamp}).
    \item The data is ordered chronologically and divided into training, validation, and test partitions using the temporal split described in Section~\ref{sec:temporal-split}.  The \emph{validation and test partitions remain entirely clean} throughout: only the training partition is subjected to PuckTrick noise injection.
    \item A PuckTrick \texttt{OBJ} is instantiated on the training partition, and the selected corruption method is invoked with a strategy dictionary specifying the target feature, the desired corruption percentage $p$, and the \texttt{"new"} mode (corruption applied from zero).
    \item The corrupted training DataFrame is converted to Pandas, preprocessed with the same label encoder fitted on the global sample, scaled with the same \texttt{StandardScaler} fitted on the clean training partition, and assembled into 2D and 3D arrays.
    \item Rare classes (fewer than five samples in the training set) are filtered and the multi-class label index space is remapped to a contiguous integer range $[0, n_{\text{classes}}-1]$, ensuring that the CrossEntropyLoss does not encounter out-of-range target indices.
\end{enumerate}

This design guarantees that each experiment measures exclusively the effect of corrupting the training data: the evaluation is always performed on the same clean held-out validation flows, making all performance numbers directly comparable across experiments and seeds.

% ------------------------------------------------------------
\subsection{Computational Infrastructure}
\label{sec:infra}
% ------------------------------------------------------------

Local development and prototyping (including hyperparameter optimisation and baseline training) were carried out on a single workstation with a consumer GPU.  The full experiment grid, comprising hundreds of training runs across ten random seeds, was executed on an HPC cluster (\texttt{scratch\_share/datai/} filesystem) equipped with dedicated GPU nodes.  The Spark session was configured with 30\,GB of driver memory, a \texttt{local[*]} master (exploiting all allocated SLURM CPU cores), and a per-process GPU memory limit of 80\% to avoid out-of-memory errors during concurrent GPU-accelerated model evaluation.
